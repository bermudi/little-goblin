### P3-1. `{ name }` resolves against the filesystem, not the catalog
- **Where:** `src/agent/skill-inject.ts:32` (`readSkillBody(paths.skills(), ref.name)`), backed by `src/agent/skills.ts:257-270` (`readSkillBody` reads any `skills/<name>/SKILL.md` — no frontmatter parse, no name-match check, no catalog membership, no MAX_ENTRIES cap).
- **Rule:** design/skills.md → Skill invocation, "**The part.** … `{ name }` resolves against the catalog (manual-only included — naming it IS the operator's override of `disable-model-invocation`)".
- **Trigger/path:** a stored `{name}` part naming a directory `loadCatalog` would skip — malformed frontmatter, frontmatter `name` ≠ directory, or beyond the 128-entry cap (`skills.ts:176-183`). Both real doors only offer catalog entries (Telegram checks `catalog.entries`, `tg/skill-command.ts:154-158`; the picker lists `loadCatalog` output), so the trigger is a part replayed after its skill degraded on disk, or a shape-valid part sent raw on the app wire (`http/app-chat.ts:50-59` validates schema shape only). When it fires, the raw markdown of a broken SKILL.md is injected wrapped as `The operator explicitly invoked skill "…"` instead of degrading to the marker.
- **Test sketch:** `workspace/skills/foo/SKILL.md` with `name: bar` in frontmatter → `loadCatalog` skips foo, but `resolveSkillRef({name: "foo"}).body !== null`.
- **Why P3:** both legitimate doors pre-resolve against the catalog; only degraded-after-pick or hand-crafted wire parts hit it; the injected bytes are still operator-disk bytes.

### P3-2. Cache-hit re-validation (`rewalk`) omits the 500-directory cap
- **Where:** `src/agent/skill-fetch.ts:728-738` — `rewalk` checks `bodyBytes > BODY_MAX_BYTES || fileCount > FILES_MAX || dirBytes > DIR_MAX_BYTES` but not a dir count; `walkSubtree` (745-779) counts files only. Its comment claims "same bounds".
- **Rule:** design/skills.md → Temp skills: "the resource caps (256KiB root SKILL.md, 10MiB dir, 500 files, 500 dirs — inode-only payloads are payloads)".
- **Trigger/path:** preflight enforces DIRS_MAX from the tar listing on the fetch path (`preflight`, 564-570), so a fetched skill can never publish over the cap. But on a cache hit the listing is never re-run — `rewalk` is the only bounds re-check (`fetchSkill`, 214-223) — so a cache dir mutated after publish (local write, restore, backup tooling) with >500 directories is served `cached: true` without refusal.
- **Test sketch:** publish a skill, `mkdir` 600 empty dirs under `state/skillcache/<digest>/<name>/`, re-`fetchSkill` the URL → no `SkillFetchError`.
- **Why P3:** requires local tamper with a directory the design calls "cache, not state — deletable"; files/bytes/body stay capped, so the exposure is inodes, not content.

### P3-3. Killed temp-skill fetches leak `.fetch-*` staging dirs (up to ~74MiB each) with no sweep
- **Where:** `src/agent/skill-fetch.ts:229` (`mkdtempSync(join(cacheRoot, ".fetch-"))`), cleanup only in the live `finally` (284, `cachedCleanup`). No boot or fetch-time sweep exists anywhere (`rg` over src/scripts: the `.fetch-` prefix appears only in this file; `check-startup.ts`, `health.ts`, `index.ts` never touch skillcache).
- **Rule:** AGENTS.md guardrail "Fail loud / durable writes" is satisfied (a crash is loud); the violated expectation is the design's own hygiene bar for staging areas — the reviewer's equivalent staging gets boot hygiene (`reviewer.ts:631-648` `cleanupStaging`, called from `wireReviewer` at 208), the fetch pipeline's does not.
- **Trigger/path:** SIGKILL / power loss between `mkdtempSync` and `finally` (the window includes the 60s download and both tar phases) strands `<cache>/.fetch-XXXX/` holding `ball.tgz` (≤64MiB) plus extraction/publish trees. Repeated crashes accumulate; nothing ever reclaims them short of the operator emptying the cache by hand.
- **Test sketch:** none practical (needs process kill); a boot-time sweep mirroring `cleanupStaging` is the fix shape.

### P3-4. The wire union silently coerces a hybrid part to `{ name }`, dropping the temp ref
- **Where:** `src/skill-part.ts:38-44` — `z.union([z.object({name…}), z.object({url, path…})])`. Zod objects strip unknown keys by default, so `{name: "x", url: "https://…", path: "<cache>/…"}` parses successfully as the first branch with `url`/`path` discarded; the invocation degrades to a catalog-name lookup.
- **Rule:** design/skills.md → Skill invocation, "**The part.** … a union like the note part: `{ name }` resolves against the catalog …; `{ url, path }` is a temp skill". A value matching neither branch strictly should be refused at the wire ("Validation is zod at the wire"), not silently reinterpreted.
- **Trigger/path:** only a misbehaving or hand-crafted client — both real doors emit one shape or the other (`tg/skill-command.ts:196`, app picker). Verified by zod's documented strip-default semantics, not by execution (labeled).
- **Test sketch:** `skillPartDataSchema.safeParse({name: "x", url: "https://github.com/o/r/tree/main/x", path: "/nonempty"})` → currently `.success === true` with data `{name: "x"}`; `.strict()` objects (or a discriminating key) would reject.
- **Why P3:** fails toward a harmless catalog invocation (name must still pass NAME_RE and resolve); no plausible-path producer.

### P3-5. A legal filename containing ` -> ` or ` link to ` is misclassified as a link and the fetch is refused with a wrong diagnosis
- **Where:** `src/agent/skill-fetch.ts:439-447` — `parseListing` strips at the first literal `" -> "` / `" link to "` regardless of entry kind. GNU tar's `--quoting-style=escape` escapes non-printables, quotes and backslashes in the *name*, but a regular file legitimately named `a -> b` (or `x link to y`) lists as `-rw… a -> b` and is indistinguishable from a symlink.
- **Rule:** design/skills.md → Temp skills, pre-flight: "regular files and directories only inside the selected subtree — links and specials refuse before extraction" (the refusal itself is correct behavior; the misclassification refuses a *regular file* and reports it as a link). Also drifts from the module's own stated intent — the test "ordinary support names — spaces, parens, dotdirs, @scope — extract intact" (`skill-fetch.test.ts:288-304`).
- **Trigger/path:** fetch a GitHub skill dir containing a support file whose name embeds ` -> `. `preflight` throws `link inside selected skill: <path>` — a typed `invalid` refusal whose message names an innocent file as a link; the operator cannot fetch a legitimate skill and the error misleads the debug.
- **Why P3:** fail-closed (never wrong acceptance), exotic filename, no security impact.

### P3-6. A corrupt cache descriptor surfaces as an untyped error (HTTP 500), where an absent one is typed `invalid` (422)
- **Where:** `src/agent/skill-fetch.ts:345-361` (`readDescriptor` throws a plain `Error` on malformed JSON / schema violation) vs `fetchSkill:206-212` (absent descriptor → typed `SkillFetchError` "invalid"). The doors map only `SkillFetchError` (`http/operator.ts:1131-1137`: oversized→413, unreachable→502, else 422; `throw err` otherwise), so the same semantic condition — broken cache — yields 422 when the file is missing and 500 when it is corrupt.
- **Rule:** design/skills.md → Temp skills: "A cache dir whose descriptor is absent or corrupt is a broken cache, not a cache miss: it fails loud, never re-extracts over or repairs the incumbent". Failing loud holds in both cases (verified by tests at `skill-fetch.test.ts:598-614`); the *typing* is inconsistent across the two halves of the same ruling.
- **Trigger/path:** corrupt `skill.json` in a digest dir, then `POST /operator/skills/preview` → 500 instead of a 4xx carrying the reason.
- **Why P3:** both outcomes refuse and preserve the incumbent; only the status class and message routing drift.

### P3-7. The injected-body log line is not the design's `skill invoked` line — name, source host, and byte-accuracy drift (out-of-scope file — pointer for hunt 3)
- **Where:** `src/turn/view.ts:243-248` — `log.info("skill body injected", { conversation, skill: inv.name, temp: isTempSkillRef(inv.ref), bytes: inv.body.length })`.
- **Rule:** design/skills.md → Owning-turn injection: "An injected body is a log line (`skill invoked`: conversation, skill or source host, bytes) plus the durable part — activation stays answerable from the log". The implementation's msg differs, a temp skill's *source host* is absent (only `temp: true`), and `bytes` is the wrapped preamble's UTF-16 length, not the SKILL.md's bytes.
- **Why P3 / pointer:** the file is hunt 3's territory (prompt assembly around injected skills); the scoped modules (`skill-part.ts`, `skill-inject.ts`) emit no line of their own. Activation *is* answerable from the log as implemented, so this is letter-drift, not capability loss.

## 3. Could not verify / suspected without a written source

- **Symlinked cache entries bypass `isCachedSkillPath`'s intent**: the wire check and the resolver's binding re-check both operate on the *lexical* path; a symlink planted at `<cache>/<digest>/<name>` pointing elsewhere would inject an arbitrary local file (the descriptor binding passes because the link's own name matches). Requires same-user write access to `$GOBLIN_HOME/state/skillcache`, which no design doc treats as a boundary — I could not trace a written ruling either way. Lead only; not counted.
- **`## skills` listing of pending proposals does not filter manual-only** (`agent/skills.ts:231-247` loops all proposal entries). If a reviewer proposal carries `disable-model-invocation: true`, its name is advertised while pending, then disappears on approval. The design mandates listing proposals ("so an approve request works in any conversation") and separately mandates manual-only stay unadvertised — I found no ruling reconciling the two. Suspected design gap, not a code bug; not counted.
- **Deployment facts inside the seeds** (gws "v0.22.5+", agent-browser CLI behaviors, `herdr --skill` output, goblin-mail port discovery) are runtime claims — not statically verifiable, out of rules of engagement.
- **The 5-minute/10-step review budget, staging budgets, and evidence limits** are code constants with no design-mandated numbers; nothing to check them against beyond internal consistency (which holds — the ~30k-char prompt-budget comment only holds at default evidence limits, a maxed hand-edited config can exceed it; comment, not contract).
- **`reviewer-stats.ts`** reads the log by review id per the design's Instrumentation bullet; not in this hunt's scope, not read beyond confirming it exists.
- **zod union strip-semantics** (P3-4) verified against zod's documented default, not executed — the scratch-file allowance went to the seed-load verification.

## 4. Simplifications & code smells (operator-added section, P3-level)

- **Dead re-export:** `export { SKILL_NAME_RE }` at `src/skill-part.ts:14` has no importer anywhere (rg across `src/`, `app/src/`, `scripts/`, including tests — every consumer imports `NAME_RE` from `agent/skills.ts` directly). Delete the re-export; keep the alias for internal use if the parallel naming with `skill-fetch.ts:37` is wanted.
- **The skill-name rule lives in four places:** `NAME_RE` (`agent/skills.ts:20`, no length bound), `skillNameSchema` (`skill-provenance.ts:11-17`, regex + max 64 duplicated as a literal), and inline `.regex(SKILL_NAME_RE).max(64)` in `skill-part.ts:39` and `skill-fetch.ts:328`. The length bound is restated by hand each time; a drift (say one site drops `max(64)`) would desync wire validation from provenance recording without any test noticing. One shared schema/constant would collapse it.
- **ENOENT-or-throw stat/lstat blocks duplicated seven times** across the scoped files: `skill-decisions.ts:43-50, 52-59, 106-111`, `skill-provenance.ts:181-191`, `reviewer.ts:956-961, 1012-1017, 1031-1036`, `skill-fetch.ts:838-845` (the only one already extracted as a helper, and it is not shared). Each carries its own carefully-worded comment making the same promise. One `lstatOrNull`/`statOrNull` pair in a shared module would carry the comment once.
- **`parseListing` never unescapes `--quoting-style=escape` output** (`skill-fetch.ts:425-458`): escaped names (`\\`, `\033`) survive as literal backslash sequences and are then refused by the backslash check in preflight — fail-closed, but it means the escape mode's only remaining effect is to steer legal exotic names into refusal (see P3-5 for the separator ambiguity on top). Either unescape into a canonical form and validate that, or document the listing check as refusing all backslash-bearing/`->`-bearing names.
- **Repeated SQLite row shape:** the `skill_sources` row type literal is written out three times (`skill-provenance.ts:44-51, 103-112, 126-134`) around one shared `rowColumns` constant; a single named row type would keep them from drifting.
- **`reviewer gate` success line logs the post-reset streak** (`reviewer.ts:400,422`): `fallbackStreak` is zeroed before the log call, so the success that breaks an outage always reads `fallbackStreak: 0` — the streak's length is only recoverable by walking back through prior lines. Logging the pre-reset value (or both) would make each line self-contained, which is the header contract's stated bar ("the experiment must answer … from the log alone").
