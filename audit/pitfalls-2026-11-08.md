# Five recurring pitfalls

**Scope.** 2,619 commits, 2026-04-19 to 2026-11-08. Review threads on the eight PRs that touched code: #46, #55, #57, #129, #141, #142, #143, #145 (36 inline findings plus findings stated only in review bodies). PR #130 reviewed only an audit report, so it is excluded.

**Method.** I clustered by defect shape, not by module. I assigned each finding to its dominant shape; overlap is real. A commit appears where its defect is clearest. The ranking is by recurring review evidence plus spread across modules and months.

**Ranking.** Resource lifecycle and stale state drew the most review findings. Write order, error handling, and test fidelity followed. Each shape also recurs in fix commits across modules and months.

## 1. A resource released only on the happy path

**Shape.** A registration, timer, listener, temp directory, stream reader, or in-flight promise is created. Release runs only on the success branch. The failure, cancel, unmount, or shutdown path leaks it.

**Why it recurs.** Acquire and release sit far apart. The failure path is the one nobody runs by hand. A leak is invisible until uptime, disk, or memory exposes it.

**Evidence.**

- `3afd0c2c` (2026-10-23) — the voice recorder kept the microphone capturing after the composer unmounted. This was bug-hunt P1 #8.
- `2cb1881d` (2026-09-19) — shutdown awaited the per-conversation queues to drain, but not dropped turns' `onDone`. `doGenerate` rethrew a stream error without cancelling the reader.
- `e6cba258` (2026-09-17) — partial downloads had no cleanup path.
- `d6cfa5c8` (2026-10-20) — in-flight approval posts and taps were not joined at shutdown. A credential delivery could be cut mid-await.
- `4056ad49` (2026-10-23) — test fixtures leaked 86k `mkdtemp` dirs, about 15 GB, until `/tmp` hit `ENOSPC`. Bun scopes a module-level `afterEach` to the first-importing file, so only that file cleaned up.
- `4810422c` (2026-04-26) — terminal subagent instances grew without a bound. Atomic meta writes cleaned the temp file only on some paths.

**Review rounds.**

- PR #46: “An unattached, unreleased reservation blocks cancellation forever.”
- PR #46: “`cancelBySession` persists `"suppressed"` but never updates `deliveryState`, so the instance and its registration leak.”
- PR #46: “Legacy spawn-tree subagents are counted but never cancelled.”
- PR #46: “`invalidatedRuntimes` and `cancelledEpochs` grow without bound.”
- PR #55: “Clear `sealingResponse` after the seal completes.”
- PR #141: “Interrupted launches leave servers running” — both child PIDs were saved only after startup succeeded. `down` could not stop children started before the record.
- PR #141: “Cleanup finishes before shutdown” — `down` moved the home to trash before the processes exited. Later log writes recreated it.

**Guard.** Give each acquire one owner with a `dispose`, `finally`, or unmount path. Test the failure path. Assert the registry, timer, and temp-dir count return to baseline. The fixture sweep in `src/testkit.ts` is the model: it made the leak self-healing and pinned the sweep with a test.

## 2. State read before an await, acted on after

**Shape.** The code reads an authority stamp, baseline, sequence, or row. It awaits. It then acts on the old value. A concurrent write, reattach, rewind, or retry makes the value stale.

**Why it recurs.** The async boundary is invisible in review. The happy path never interleaves a competing write. The failure needs a second actor at the wrong moment.

**Evidence.**

- `7c336eb4` (2026-08-20) — a review round found that a binding fence was not checked at commit, and that steering attach did not validate current-runtime authority first.
- `09766266` (2026-10-22) — an unresolved send was fenced on the mutable attachment row. A reattach re-keyed it onto the replacement agent. That fenced the destination that never received the send, and freed the one that did.
- `012db9b3` (2026-10-20) — a fresh attach to a dispatch identity with an unresolved delivery minted a new attachment id past the fence.
- `923e9d4d` (2026-10-24) — a rewind deleted the history seq a claimed wake carried. Reconcile could resubmit a dead seq. The claim epoch bump now fails it closed.
- `2398cdec` (2026-11-02) — queued developments now stamp status, revision, and attachment generation. The wake commit re-checks all three in its transaction.
- `913d9b66` (2026-11-07) — a chat reopened during the undo window stayed open after `DELETE`. The deleted row reappeared while the refresh was pending.
- `054aa307` (2026-09-24) — a notice send resolving after clear-and-replace could mute the successor episode forever. Marks are now episode-scoped.

**Review rounds.**

- PR #143: “Finished tasks look stalled” — delivery recorded the completion sequence as the new baseline, so the watcher waited for a sequence that would never come.
- PR #57: “Resend retains stale failure” — a successful resend could not clear the old delivery generation's failure.
- PR #46: “Recheck runtime authority before delivery.”
- PR #46: “`setSurfacePreferences` does not reconcile a pending project assignment.”
- PR #145: “Finished results leave Attention” — the feed filtered on open status, so a completed item vanished before the next poll.
- PR #141: “Reused instances run old code” — `up` checked only a process marker, so a branch switch reused a server from different code.
- PR #141: “Concurrent launches share one home” — two `up` calls passed the state check before either saved, then overwrote the same PID record.
- PR #141: “Client builds miss shared changes” — the rebuild check watched `app/` only, but the client imports `src/tags.ts`.

**Guard.** Carry one authority stamp (epoch, revision, identity) and read it at the moment of action. Do not read a mutable row before an await and trust it after. Add a test that interleaves the competing write between read and act.

## 3. Effect and record written in the wrong order

**Shape.** The side effect happens before the durable claim. Or the successful record lands before the effect is confirmed. A crash, timeout, or Ctrl-C between the two leaves memory, disk, and the outside world disagreeing.

**Why it recurs.** The effect is the obvious line. The record is bookkeeping, so it lands on either side by accident. The two are often written by different calls.

**Evidence.**

- `7c336eb4` (2026-08-20) — first-message creation and bootstrap admission were not atomic. A rejected admission could leave an empty conversation.
- `c857d4b2` (2026-10-31) — mail now claims the outbox row before the Gmail send. A crash survivor reads busy, so the sweep never resends it.
- `f0903107` (2026-11-08) — release waited for idle after flipping `live`. Ctrl-C during the wait could leave the new release live while the old process kept running.
- `7bea15c3` (2026-10-19) — a nested write inside the handover transaction guaranteed `SQLITE_BUSY` and rolled every handover back. The follow-up link now lands after commit.
- `1dbc9fbc` (2026-11-06) — the Telegram sent marker and reply route now save together. A timed-out send stays open, so its late result is recorded and the sweep does not send twice.
- `4810422c` (2026-04-26) — in-memory status was mutated after `persistMeta` succeeded, not before.
- `8ce7f1b4` (2026-09-17) — settings patches and the epoch bump now land in one transaction. A settings write can no longer land without fencing in-flight turns.

**Review rounds.**

- PR #46: “Set `deliveryState` only after the record write succeeds.”
- PR #46: “Guard `createRecord` against an existing record.”
- PR #46: “Preserve the changed-head state across the installer handoff.”
- PR #55: “Later success erases partial failure.”

**Guard.** Claim durably, then act, then settle. Put paired fields in one transaction. Add a crash-point test that stops the process between each pair.

## 4. Error swallowed, or the wrong error promoted

**Shape.** A missing value becomes a normal empty result. A transient read failure is treated as a fatal write failure. A batch stops on one bad record. The operator sees success, silence, or a dead feature.

**Why it recurs.** Every boundary has three error kinds: missing, transient, fatal. Code often collapses them to two. A `catch` that logs and continues is right for one item and wrong for the pass.

**Evidence.**

- `35bcc353` (2026-08-31) — doctor local checks dropped every non-`ENOENT` filesystem error.
- `91c26d0f` (2026-10-22) — a provider `SUCCESS` with no result array mapped to `""`, which the orchestrator read as “no speech”. It now throws and names the id.
- `1eb5649c` (2026-10-19) — a guarded `UPDATE` that changed 0 rows logged success. The event stayed unregistered.
- `cb1fcdd0` (2026-10-22) — a skill submit ignored the admission refusal and stamped success on a fenced turn.
- `b0899d9c` (2026-10-14) — every claim error was treated as a lost lease. One podman blip terminal-failed a live computer run.
- `3cda45c6` (2026-10-31) — a delivery drain gave up unsent chunks without telling the chat.
- `2c1d5b6c` (2026-09-30) — a thrown command handler killed the process, although commands bypass the inbox and had nothing to replay.

**Batch isolation, same shape.**

- `7bea15c3` (2026-10-19) — one corrupt wake stalled every other wake's delivery.
- `473bc07b` (2026-10-19) — one observer target group could fail the whole pass. Each group now isolates, and the pump runs from `finally`.
- `4c6b7ad4` (2026-10-31) — one skill failure failed the whole proposal batch.
- `49a6d4e4` (2026-10-31) — corrupt proposal rows now skip-and-log in listings.

**Review rounds.**

- PR #143: “Read errors stop running tasks” — a failed observation after a successful send marked the whole delegation failed and closed its workspace.
- PR #55: “Check `responseFailed` before `responseAccepted` so the real cause propagates.”
- PR #46: “One malformed record stops reconciliation for every other run.”
- PR #46: “Unguarded delivery acknowledgement can discard a successful subagent result in both tools.”
- PR #46: “Move cleanup errors outside `finally`.”

**Guard.** Classify each boundary error as missing, transient, or fatal. Report success only after a confirmed effect. In a batch, isolate each item, log the skip, and keep the pass moving.

## 5. Test encodes the environment, not the contract

**Shape.** The test freezes a clock the code ignores. It assumes a tool or writable path the runner lacks. It pins a fake shape instead of the wire. It asserts a string that passes when the guard is absent.

**Why it recurs.** The test is written against the developer's machine and the happy path. CI and time expose the difference. A test that cannot fail hides the next regression.

**Evidence.**

- `3551c5c8` (2026-09-11) — verifier-only red-green tests for five review findings. The failing assertions landed before the implementation.
- `3acc0ba5` and `1bba7297` (2026-11-08) — a view test froze `NOW`, but the component read `Date.now()`. The suite went red once the fixture's date passed in real time.
- `8f75262c` (2026-11-08) — the same real-clock read stayed latent in a sibling test.
- `15934e1b` (2026-11-06) — three CI-only failures. A test called `trash`, which the runner lacks. Release tests used 5s timeouts for real `bun`, `git`, and `tar`. An abort test read `/proc` immediately after `SIGKILL`.
- `37f5cac7` (2026-11-05) — the release suite assumed a full checkout (`HEAD~1` in a depth-1 clone). The notes test needed more than the default timeout for fsynced writes.
- `7a0f8a66` (2026-11-06) — tests without `useHome()` wrote about 960 dirs into the real `~/goblin`.
- `4056ad49` (2026-10-23) — the fixture cleanup hook was scoped to one file, so the full suite leaked.
- `630729f9` (2026-11-02) — a review nit: the test did not pin the rethrown fields, the warn line, or the 5xx retry ladder.

**Review rounds.**

- PR #145: “Test helpers cannot run” — `/dev/shm` passed the space check but was mounted `noexec`.
- PR #55: “Remove `sleep(50)` and assert immediately after `deliverCompletion`.”
- PR #55: “Assert the invocation index as part of the identity phrase, not as a bare `"0"` substring.”
- PR #46: “The assertions verify the host guard, not the runner.”
- PR #141: “Project selector matches several inputs” — the guide selector matched the name field and two radios.

**Guard.** Inject the clock, temp root, and process runner. Assert the contract and one failure path. Prove the test fails when the fix is reverted.

## Almost made it: limits that disagree

Two PR #145 findings share one shape: the producer accepts more than the consumer can carry.

- `runReport()` cut worker questions at 4,000 characters. `ask_operator` accepted 16,000. A valid question lost its ending.
- The closing report capped `evidence` at 32 items. `understandingSchema` allowed any number of completion items. A 33-item responsibility could never close.

The same shape appears in `7ab1ef06` (chat part payloads now zod-validated before persistence) and `6fe36d87` (port and model validation). One shared limit constant at the boundary would remove the class.

## What to encode first

`AGENTS.md` says the same lesson twice becomes a lint, test, or script. Each of these five has passed twice.

1. **Disposable scope.** One acquire and release owner. A leak test on the failure path.
2. **Authority stamp.** One epoch, revision, and identity value. Read it at action time.
3. **Claim, effect, settle.** One helper for durable side effects. Crash-point tests.
4. **Boundary error taxonomy.** Missing, transient, fatal. Per-item isolation in batch loops.
5. **Test seams.** Clock, temp root, and process runner injected by default in the testkit.

The import-cycle guard is the pattern to copy: freeze current debt, fail on growth, prune by hand.
