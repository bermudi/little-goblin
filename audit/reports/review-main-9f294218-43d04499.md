## Findings

### [P1] Keep the run identity available when authority setup fails

Location: `src/runtime.ts:933-935`.

`authority` is assigned only after `openToolAuthority` returns, but that
function commits `beginRun`, links wake ownership, and then reads
`journal.callsFor` to construct the recovery guard. If that read throws, the
record's run-id getter still returns null. Both the journal-fault handler and
the finally backstop therefore skip the terminal stamp, leaving the committed
row running and linked wakes waiting until restart. Preserve the identity as
soon as the row exists, or make failed initialization terminate its row.

### [P2] Preserve parked machine targets when re-enabling delegation

Location: `src/http/operator.ts:422-430`.

After delegation is switched off and saved, its machine targets live under
`parked.delegation`, not `normalized.delegation`. Enabling it through the new
editor submits only harnesses and defaults. This merge reads machines only
from the active block, then deletes the parked copy. The save silently loses
all configured machine targets. Preserve the file-only fields from the parked
block when there is no active block.

### [P2] Honor the existing Capabilities off switch when serializing delegation

Location: `app/src/settingsDraft.ts:759-763`.

The Delegation switch in Settings → Capabilities changes only
`draft.capabilities.delegation`; it leaves `draft.delegation` populated.
The new `capEmit` call therefore emits an active object alongside
`capabilities.delegation: false`. The server parks the block, then its body
merge immediately restores it. The UI can report a successful save while the
delegate tool remains enabled after restart. Synchronize the two editor states
or ensure an off flag prevents emitting the active block.

### [P2] Accept defaults that name machine-side harnesses

Location: `app/src/settingsDraft.ts:593-596`.

The server schema explicitly permits a default to name a harness declared only
under a machine target. The settings draft contains only local harnesses, so
this validation rejects such an unchanged default as unlisted. Since
`SettingsView` validates the whole draft before every save, any unrelated edit
is blocked for that valid configuration. Preserve or validate against the
machine-side harness names as well.

### [P2] Leave the optional default role unset when editing other roles

Location: `app/src/SettingsDelegation.tsx:35-38`.

For a valid configuration containing only `defaults.review`, editing that role
calls `withDefault`, which adds `{ role: "default", harness: "" }` to the saved
draft. Validation then refuses every save because that synthetic role has no
agent, and the default row has no remove button. The same issue prevents
clearing a default with the offered “none” option. Keep the empty default row
display-only or treat it as an absent mapping.

### [P2] Apply the provider's zero-retry rule to transient stream retries

Location: `src/turn/stream.ts:585-591`.

The new callback-directed transient retry ignores `deps.step.maxRetries`.
A 1min step carries zero because every POST is billed; only content-filter
retries are an explicit exception in `design/model.md`. A transient error part
now triggers another billed request despite that rule. The new transport
middleware already respects the provider-specific zero budget; the mid-stream
branch must do so too.

### [P2] Do not append unlanded progress when the final reply is already durable

Location: `src/turn/unlanded-progress.ts:190-195`.

`Runtime.runAttempt` appends the final reply before awaiting terminal delivery,
then marks the journal run completed only after that await. Telegram delivery
can include network calls and voice synthesis. If the process dies during
delivery, this hook sees a running row and appends another transcript event
claiming the request has no final reply, although that reply is already stored.
The in-memory `markReplyLanded` flag cannot protect boot recovery. Persist the
landed-reply fact and consult it before appending interrupted progress.

### [P3] Share the duplicated abortable retry delay

Location: `src/agent/providers.ts:51-62`.

This new `awaitRetryDelay` duplicates the implementation in
`src/turn/stream.ts:208-220`; only optional signal access differs. Both implement
the same timer and abort-listener lifecycle. There are already two concrete
callers, so use one shared implementation rather than maintaining two copies
of the cancellation behavior.
